# Homepage PM Roadmap

本文件是首頁與 PM 工作流的長期改善計劃。後續若要調整首頁、Dashboard、每日更新、候選股、持股風控或 PM Worklist，先閱讀：

1. `backend/docs/current_rules.md`
2. `backend/docs/signal_rules.md`
3. 本文件

目標不是把所有資訊塞到第一屏，而是讓使用者一打開系統就知道：

- 今天資料是否可用
- 現在最該處理哪一件事
- 哪些持股或候選股需要注意
- 後續細節要去哪裡看

---

## 1. 產品定位

首頁應該是「決策工作台」，不是所有報表的集合頁。

目前系統已經有大量後端輸出：`summary.json`、`universe_report.csv`、`daily_brief.json`、`daily_check.json`、Update Workflow、PM Worklist、持股分析、基本面避雷補資料、候選股復盤。首頁的責任是整理這些資訊的優先順序，讓使用者先完成今天最重要的操作，再往下看細節。

首頁第一屏只回答四件事：

| 問題 | 首頁應呈現 |
|------|------------|
| 今天資料能不能用 | 資料日、最新收盤日、交易輸出是否可用、是否過期 |
| 我現在要先做什麼 | 單一 Primary Action，含可複製指令或安全 API 動作 |
| 今天盤勢風控是什麼 | 大盤 posture、人工筆記是否過期、持股水位語氣 |
| 哪些股票最需要看 | 持股風險、可小試候選、待復盤候選各最多 3 筆 |

---

## 2. 現況問題

### 2.1 第一屏資訊過量

目前首頁同時顯示多個工作流卡片、資料狀態、交易輸出、阻塞、提醒、基本面、持股決策、候選股復盤與檔案狀態。這些資訊都重要，但同時出現在第一屏時會造成三個問題：

- 使用者不知道哪一個紅色或黃色才是最急的。
- 很多資訊是「狀態說明」，不是「下一步」。
- 候選股與持股決策被系統維護資訊淹沒。

### 2.2 動作與資訊混在一起

有些卡片是要使用者執行指令，有些只是顯示檔案狀態，有些是策略摘要，有些是候選股列表。首頁需要先區分：

- 阻塞型動作：不處理就不能用今天資料做判斷。
- 建議型動作：不處理仍可閱讀，但會降低完整性。
- 觀察型資訊：幫助理解盤勢，不一定要立刻操作。
- 明細型資料：應放在第二屏或專頁。

### 2.3 首頁缺少決策層級

目前看得到很多資料，但缺少一個清楚的優先順序：

1. 先確認資料流是否完成。
2. 再確認交易判斷是否可用。
3. 再處理持股風險。
4. 再看候選股入場。
5. 最後才看基本面補資料與長期維護。

### 2.4 價格口徑需要更醒目

系統多數價格來自 `backend/data/ohlcv.csv` 的最新收盤價，不是盤中即時市價。首頁與決策表應明確顯示「最新收盤」與資料日期，避免使用者誤以為是即時報價。

## 3. 首頁目標資訊架構

### 3.1 第一屏：Decision Console

首頁第一屏改為一個清楚的決策工作台，最多四個區塊。

| 區塊 | 內容 | 資料來源 |
|------|------|----------|
| Status Strip | 資料日、最新收盤日、交易輸出可用性、最後更新時間、價格口徑 | Update Workflow / Daily Check |
| Primary Action | 今天最該做的一件事，附可複製指令、預期產物、狀態原因 | PM Worklist 第一筆 / Update Workflow |
| Market Posture | 大盤風險、人工盤後筆記日期、持股水位語氣、盤勢是否過期 | daily_brief / manual note |
| Today Focus | 持股風險、可小試候選、待復盤項目，各最多 3 筆 | portfolio analysis / universe report / decision journal |

第一屏不顯示完整表格、不顯示全部檔案清單、不顯示大量候選股。明細放到第二屏或專頁。

### 3.2 第二屏：PM Worklist

第二屏顯示完整 PM Worklist，依優先順序分組：

1. 阻塞：資料過期、交易輸出不可用、Daily Check 過期。
2. 持股風險：停利、停損、跌破關鍵支撐、需要補紀錄。
3. 候選股：可小試、等回測、待復盤。
4. 基本面：基本面避雷資料不足、欄位缺漏。
5. 維護：檔案健康、資料修復、醫生檢查。

每個工作項目都應有：

- `status`
- `reason`
- `next_action`
- `action_payload`
- `expected_outputs`
- 明確說明是否會修改交易紀錄或持倉

### 3.3 第三屏：候選股與持股明細

候選股與持股表格應保留完整資訊，但預設要能掃描：

- 預設排序：今日動作、持股風險、可進場品質、R/R。
- 預設折疊長文字，只露出主要原因。
- 每列提供「詳細」進入單檔分析。
- 進場、出場、停損價位要標示來源，例如 MA20、前高、爆大量低點。

### 3.4 系統維護區

檔案狀態、資料來源、完整輸出檔案清單、doctor 結果放在頁面後段。這些資訊重要，但不應搶第一屏。

## 4. 長期階段計劃

### Phase H0：首頁盤點與契約固定

目標：先不改 UI，確認首頁需要哪些後端契約。

工作項目：

- 盤點目前首頁使用的 API、欄位與卡片。
- 確認 `/api/system/update-workflow`、`/api/system/pm-worklist`、`/api/system/daily-check` 是否足以提供第一屏資料。
- 補齊缺少的 `primary_action` 或排序規則，不讓前端自行判斷策略。
- 建立首頁第一屏 acceptance checklist。

驗收：

- 文件列出首頁第一屏所需欄位。
- 後端可明確提供「今天最該處理的一件事」。
- 不需要前端解析大段文字才能顯示重點。

### Phase H1：第一屏減壓

目標：把首頁第一屏重組為 Decision Console。

工作項目：

- Status Strip 只顯示資料日、交易輸出可用性、價格口徑、最後更新。
- Primary Action 只顯示一件最重要待辦。
- Market Posture 改成短摘要，不顯示長篇人工筆記。
- Today Focus 限制每類最多 3 筆。
- 把檔案清單、完整工作流與系統維護移到下方。

驗收：

- 1366px 桌面第一屏可看完主要狀態與下一步。
- 第一屏紅色警示最多來自一個 primary blocker。
- 使用者不用滾動就知道是否能使用今天交易輸出。

### Phase H2：工作項目操作標準化

目標：所有可操作事項用同一套 action renderer。

工作項目：

- 支援 `command`：顯示短指令與完整複製指令。
- 支援 `copy_text`：顯示 preview_items 與完整複製內容。
- 支援 `api`：顯示安全動作按鈕。
- 支援 `file`：顯示輸出路徑與用途。
- 每個動作都顯示 expected_outputs。

驗收：

- PM Worklist、Daily Check、Update Workflow 的按鈕邏輯一致。
- 前端不再針對不同來源寫重複判斷。
- 使用者知道動作跑完要檢查哪些檔案。

### Phase H3：候選股與持股決策改善

目標：讓首頁能快速分辨「可進場」「等回測」「持股風險」「不該買」。

工作項目：

- 候選股摘要分成：可小試、等回測、暫不碰。
- 持股摘要分成：續抱、停利觀察、出場警示、資料不足。
- 每筆顯示進場區間、停損、停利或壓力位。
- 明確標示 R/R 不足、RSI 過熱、距 MA 過遠等原因。
- 提供「詳細」跳單檔技術分析。

驗收：

- 使用者能在 30 秒內找出今天最需要看的 3 支股票。
- 未達進場條件的股票有清楚 `no_buy_reason`。
- 持股風險不被候選股資訊淹沒。

### Phase H4：人工盤後筆記與市場姿態整合

目標：人工筆記變成首頁短摘要，而不是長文字區塊。

工作項目：

- 顯示人工筆記日期、是否過期。
- 顯示持股水位語氣，例如五成、七成、保守、可小試。
- 顯示焦點族群與風控條件。
- 若筆記過期，首頁只顯示需更新，不沿用舊 playbook。
- 提供更新筆記入口，但不自動覆蓋正式訊號。

驗收：

- 首頁能一眼看出目前市場 posture。
- 人工筆記過期時，不會被誤當成今天結論。
- 大盤濾網與人工筆記語氣有來源日期。

### Phase H5：視覺與可用性驗收

目標：用截圖與使用流程確認首頁真的變友善。

工作項目：

- 建立桌面與手機寬度的截圖驗收流程。
- 測試資料正常、資料過期、Daily Check 過期、候選股為空、持股為空等狀態。
- 檢查文字是否溢出、卡片是否過多、按鈕是否清楚。
- 確認紅 / 黃狀態代表真實優先順序，不造成警示疲乏。

驗收：

- 第一屏不需要解讀大量卡片。
- 主要 CTA 在不同狀態下都明確。
- 空狀態與錯誤狀態都有下一步。

## 6. 實作原則

### 6.1 前端不得重建策略邏輯

首頁可以排序與折疊資料，但不可自行判斷：

- 哪支股票可買
- 哪支股票要賣
- 哪個訊號更強
- 哪個大盤水位生效

這些判斷必須來自後端 service 與輸出欄位。

### 6.2 Router 不做計算

若需要新增首頁摘要或 primary action，應在 `backend/app/services/**` 實作，router 只負責 HTTP response。

### 6.3 第一屏限制

第一屏最多四個主要區塊，不放完整表格，不放長篇筆記，不放完整檔案清單。

### 6.4 明細保留，但往下移

減少第一屏資訊不代表刪除資訊。完整 PM Worklist、候選股表格、持股明細、檔案狀態與 doctor 結果仍應保留在下方或專頁。

### 6.5 所有動作都要能解釋

任何「更新資料」「重新產生訊號」「補基本面」「建立復盤」都必須顯示：

- 為什麼要做
- 會做什麼
- 是否會修改交易紀錄或持倉
- 完成後檢查哪些輸出

## 7. 首頁完成定義

首頁改善不是 UI 變漂亮就算完成，必須滿足：

- 開啟首頁 5 秒內知道資料是否可用。
- 開啟首頁 10 秒內知道最該做的下一步。
- 第一屏只出現一個最高優先警示。
- 能清楚看出價格是最新收盤，不是即時市價。
- 持股風險優先於候選股追蹤。
- 候選股能看出可小試、等回測或暫不碰。
- 每個動作都能複製或執行，且知道預期產物。
- 空資料、過期資料、資料不足都有明確原因與下一步。
