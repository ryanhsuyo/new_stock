# 個人台股決策產品差距與落地 Roadmap

狀態：產品規劃基準  
日期：2026-06-22  
目標：做成每天可可靠使用的個人台股決策工具，不以公開 SaaS 或自動下單平台為目標。

## 1. 結論

目前專案已不是單純 demo：資料回補、訊號、API、Dashboard、持股、交易紀錄、Daily Check 與可解釋輸出大致連通，也有完整後端測試保護。

但它仍比較接近「功能豐富的個人研究系統」，還不是能長期信任的產品。與成熟產品最大的差距不是少幾個技術指標，而是：

1. 缺少可重現、無未來函數的策略回測，無法回答訊號歷史上是否有效。
2. 資料健康仍以檔案與平日規則為主，尚未完整處理交易所休市日、資料覆蓋率與來源追溯。
3. 缺少完整的備份／還原與災難復原驗收，個人交易與復盤資料仍有單點風險。
4. 每日流程已有很多零件，但還需要明確的產品級成功條件、失敗復原與歷史稽核。
5. 即時行情、即時警示、模擬交易與券商整合尚未具備，但這些不是第一階段必要條件。

因此，下一步不應繼續堆策略或指標。應先完成「可信度、可靠度、可恢復性」三件事。

## 2. 市場產品基準

比較目的不是複製成熟平台，而是確認使用者已習慣哪些能力。

| 產品／服務 | 已驗證的市場能力 | 本專案應學習的部分 |
|---|---|---|
| [XQ 全球贏家](https://www.xq.com.tw/) | 台股資料、選股、策略回測、盤中監控、模擬／自動交易與跨裝置 | 選股結果必須可驗證；監控與下一步要形成閉環 |
| [XQ 贏家選股](https://www.xq.com.tw/xqapptw/) | 多條件選股、歷史回測、雲端監控與通知 | 使用者不只要看到推薦，還要知道策略過去表現與何時失效 |
| [TradingView 功能](https://www.tradingview.com/features/) | 圖表、screeners、Pine 策略、警示、財務資料與模擬交易 | 規則、圖表、警示與驗證應使用同一套條件 |
| [TradingView Strategy Tester](https://www.tradingview.com/support/solutions/43000764138/) | 歷史策略報告與模擬交易 | 回測必須產生績效、交易明細與可重現參數 |
| [TradingView Alerts](https://www.tradingview.com/support/solutions/43000520149-about-tradingview-alerts/) | 價格、指標、策略與 watchlist 的跨裝置警示 | 警示應由條件變化觸發，而不是只通知批次成功 |
| [Fugle 行情 API](https://developer.fugle.tw/docs/data/intro) | REST 歷史／日內行情與 WebSocket 即時行情 | 若未來做盤中版，應採合法、穩定的行情來源，不自行拼湊爬蟲 |
| [Fugle 交易 API](https://developer.fugle.tw/docs/trading/intro) | 台股程式交易 SDK；正式交易前有申請與模擬流程 | 真實下單必須在模擬、風控、稽核完成後才評估 |

成熟產品的共同點是資料穩定、結果可驗證、操作有回饋、錯誤可恢復。指標數量只是次要差異。

## 3. 本專案目前已有能力

依目前程式、測試與文件，已具備：

| 能力 | 現況 | 產品判定 |
|---|---|---|
| TWSE／TPEX 日線回補 | 有節流、SKIP 原因、merge 去重與排序 | 可用基礎 |
| 訊號資料流 | backfill → signals → JSON／CSV → API → Dashboard | 已跑通 |
| 可解釋性 | `reasons`、`risk_note`、`no_buy_reason`、Daily Check | 明顯優勢 |
| 技術分析 | 支撐壓力、趨勢、breakout／breakdown、型態、R/R | 第一版可用 |
| 多策略視角 | core 作為內部風控，對外保留老王與穩健動能兩種策略，基本面只作避雷輔助 | 可用但需績效驗證 |
| 持股與交易 | 交易紀錄推算持倉、均價與投組摘要 | 個人使用可用 |
| 工作流 | Update Workflow、PM Worklist、Today Focus、資料修復 | 已有良好骨架 |
| 可靠性 | 原子寫入、單股 timeout、排程健康、615 個後端測試 | 工程基礎良好 |
| 前端 | Dashboard、候選股、技術分析、持股與復盤入口 | 可操作但仍偏內部工具 |

本專案的差異化不是取代 XQ 或 TradingView，而是提供「台股盤後決策、持股風控與不買原因」的個人工作流。

## 4. 真正阻礙產品可用的差距

### P0：沒有就不能長期信任

#### P0-1 策略回測與可信度

目前訊號規則可執行，但缺少完整歷史績效證據。

必須補齊：

- 逐日執行現有正式 signal，不允許讀取未來資料。
- 納入手續費、交易稅、滑價與最小交易單位假設。
- 輸出總報酬、最大回撤、勝率、平均盈虧、交易次數與基準比較。
- 分開呈現樣本內、樣本外或 walk-forward 結果。
- 每筆交易保留進出原因、當時規則版本與資料基準日。
- 不以高勝率作為驗收；以計算正確、可重現、無 look-ahead bias 為驗收。

#### P0-2 資料完整性與交易日

- 建立正式交易日／休市日來源，不能只以週一至週五判斷 stale。
- 每次更新輸出追蹤股票總數、成功數、缺資料數、最後資料日與來源。
- 區分「市場休市」「來源尚未更新」「單股缺資料」「抓取失敗」。
- 資料修復後必須自動重跑 signals 與 Daily Check，並驗證產物基準日一致。
- 保存資料來源與更新批次 ID，讓訊號可追溯到輸入版本。

#### P0-3 備份、還原與個人資料安全

- 一鍵備份 `trades.json`、decision journal、watchlists、market notes 與必要設定。
- 備份需有時間戳、checksum、保留份數與不覆寫策略。
- 還原預設 dry-run，列出將變更的檔案；正式還原前再確認。
- 用臨時目錄做自動還原測試，證明備份可讀，不只證明檔案存在。
- 憑證、API key 與券商設定不得進入 Git 或一般備份檔。

#### P0-4 每日閉環驗收

一個交易日的完整成功條件應固定為：

```text
資料更新成功
→ 追蹤清單覆蓋率達標
→ signals 與 universe_report 基準日一致
→ Daily Check 可用
→ Today Focus 有結果或清楚空原因
→ 使用者可記錄決策
→ 隔日可比較計畫與實際結果
```

任何一步失敗，首頁只能顯示 blocker 與修復動作，不得把舊候選包裝成今日建議。

### P1：讓它成為好用的每日產品

1. **策略結果追蹤**：每日保存 signal snapshot，比較昨日計畫、今日結果與是否觸發失效條件。
2. **來源可觀測性（R5.1 已完成第一版）**：`support_source`、`resistance_source`、`entry_source`、`stop_source`、`target_source` 已寫入 signals / universe_report / daily_brief / signal snapshot。
3. **有效警示（R6.1 已完成本地摘要第一版）**：`signal_alerts.json` 與 Daily Check top action 只提示新出現的隔日訊號變化；Slack / macOS / email 通知仍是後續工作。
4. **產品啟動流程**：單一啟動／停止／健康檢查入口，不要求記住多組 backend／frontend 指令。
5. **設定與規則版本（R7.1 已完成稽核第一版）**：輸出附 `rules_version` / `rules_metadata`；動態參數設定與 UI 仍是後續工作。
6. **持股風控精度**：完整納入費用、交易稅、已實現／未實現損益與部位集中度。

### P2：有價值但不是第一優先

- 合法即時行情與盤中 watchlist 監控。
- K 線成交量子圖、更多週期與更成熟的繪圖工具。
- 模擬交易帳戶與 forward test。
- 自訂選股條件與策略參數 UI。
- 更多基本面、籌碼面與事件資料。
- 券商 API；只有模擬、風控、稽核與人工確認成熟後才評估。

## 5. 不應現在做的項目

- 不用複製 XQ 的數百種條件或 TradingView 的完整繪圖能力。
- 不應在沒有回測前增加更多策略與分數權重。
- 不應先上資料庫、多使用者登入、訂閱計費或公開網路部署。
- 不應把即時行情直接寫入正式盤後 signal，兩種資料口徑必須隔離。
- 不應自動下單；個人工具先維持「決策支援 + 人工確認」。
- 不應以漂亮 Dashboard 取代資料正確與結果驗證。

## 6. 建議執行順序

| 階段 | 內容 | 預估 | 完成定義 |
|---|---|---:|---|
| R0 | 固定產品契約與基準 fixture | 1–2 天 | 一份固定資料可完整跑完每日閉環 |
| R1 | 最小可信回測器 | 第一版完成 | 單股 core 已具無未來資料防線、成本、交易明細、績效與 buy-and-hold 基準 |
| R2 | 交易日、覆蓋率與資料 lineage | 第一版完成 | 本地休市 / 補班交易日、coverage report、batch_id lineage 與 coverage blocker |
| R3 | 備份／dry-run 還原 | 第一版完成 | 個人資料可整包備份、dry-run 預覽與確認後還原，且還原前自動建立 pre-restore backup |
| R4 | signal snapshot 與隔日復盤 | 第一版完成 | 每次 signals 保存當日計畫 snapshot，並產生前一份計畫對本次訊號的 action 變化 review |
| R5 | 來源欄位與差異警示 | 3–5 天 | 價位可解釋；只通知新風險與狀態變化 |
| R6 | 即時行情／模擬交易評估 | 選配 | P0/P1 穩定後另立設計，不直接混入盤後資料流 |

## 7. 產品級驗收指標

| 類別 | 最低驗收 |
|---|---|
| 可重現 | 相同資料、規則版本與參數產生相同 signals 與回測結果 |
| 資料完整 | 每次 run 有 coverage report；缺資料股票與原因可列舉 |
| 資料一致 | summary、universe report、Daily Check 的 `as_of` 不互相矛盾 |
| 失敗透明 | 網路、來源、timeout、格式錯誤都留下代碼、步驟與可執行修復方式 |
| 回測可信 | 無 look-ahead；含成本／滑價；有交易明細、回撤與基準比較 |
| 可恢復 | 備份可由自動測試還原；正式還原具 dry-run 與確認步驟 |
| 決策閉環 | 每個候選都有買／不買原因，每個持股風險都有失效價與下一步 |
| 安全 | 預設只監聽 localhost；不儲存明文券商密碼；不自動下單 |

## 8. 下一個實作階段

R1 第一版已完成單股 `core` 日線回測。R2 第一版已補上本地交易日曆、追蹤清單覆蓋率報告與 batch lineage，讓每日輸出能追溯資料批次，且 coverage 過低時會阻擋交易輸出。R3 第一版已補上個人資料整包備份、dry-run 還原預覽、正式還原確認字串與 pre-restore backup。R4 第一版已開始保存每日 signal snapshot，並產生隔日 action 變化 review。

下一階段可進入 **R5：來源欄位與差異警示**，讓支撐、壓力、停損與通知都能追溯來源並避免重複噪音。

目前系統已從「會產生建議」前進到「能驗證單股 core 建議、稽核每日資料輸入批次、可恢復個人資料，並保存每日計畫供隔日復盤」；尚未證明整體選股投組績效。
