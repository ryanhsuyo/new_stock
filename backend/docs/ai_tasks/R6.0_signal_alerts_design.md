# R6.0 Signal Alerts Design

## Goal

Turn `signal_snapshot_review.json` into a concise alert summary that highlights only meaningful day-to-day changes.

## Scope

R6 first version writes a local JSON summary only. It does not send Slack, macOS, email, or browser notifications.

## Output

Write `backend/out/signal_alerts.json` with:

- `as_of`
- `previous_as_of`
- `generated_at`
- `status`
- `alert_count`
- `severity_counts`
- `alerts`
- `message`

## Alert Rules

- `risk_triggered` -> severity `block`, title `持股/候選轉風險`
- `action_changed` -> severity `warn`, title `隔日動作變更`
- `risk_eased` -> severity `info`, title `風險解除觀察`
- `missing_current` -> severity `warn`, title `前日計畫缺少本日資料`
- `unchanged` is not an alert.
- `no_previous_snapshot` produces zero alerts with a clear message.

## Daily Check Integration

`daily_check.py` should read `signal_alerts.json` when present and add at most one top action:

- `block` if any alert has severity `block`
- `warn` if there are alerts but none are `block`
- no extra action if there are zero alerts

The action payload should be a file pointer to `backend/out/signal_alerts.json`.

## Boundaries

- Do not change trading strategy, signal classification, or price calculation.
- Do not write generated `backend/out/*` manually.
- Do not require network access or new dependencies.
- Do not put alert rules in routers or frontend.
