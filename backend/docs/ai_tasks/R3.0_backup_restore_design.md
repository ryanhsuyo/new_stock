# R3.0 Personal Data Backup And Dry-Run Restore Design

## Goal

Add a product-grade recovery path for personal data so the system can protect trading records, decision notes, watchlists, market notes, and settings before more strategy or UI work.

## Scope

R3 backs up only user-owned personal data under `backend/data/`:

- `trades.json`
- `decision_journal.json`
- `watchlists.json`
- `market_notes.json`
- `settings.json`

R3 does not back up generated outputs, OHLCV, fundamentals, chips, stock names, or source code. Those are either regenerated data or repository assets and should not make the restore surface wider than necessary.

## Architecture

Create a focused service, `backend/app/services/personal_backup_service.py`, owned by the system layer. It creates timestamped backup directories under `backend/data/backups/personal/`, copies existing personal files, writes a `manifest.json`, and computes SHA-256 checksums for each included file.

Add API endpoints under `backend/app/routers/system.py`:

- `GET /api/system/personal-backups`
- `POST /api/system/personal-backups`
- `POST /api/system/personal-backups/restore-preview`
- `POST /api/system/personal-backups/restore`

Add a CLI wrapper, `backend/scripts/personal_backup.py`, so recovery does not depend on the frontend.

## Restore Rules

- Restore preview is dry-run only and never writes files.
- Restore preview compares backup checksums and reports which files would be created, overwritten, skipped, or missing from the backup.
- Formal restore requires `confirm="RESTORE_PERSONAL_DATA"`.
- Formal restore first creates a fresh current-state backup.
- Formal restore writes through `atomic_write_text`, never partial direct writes.
- Backup id and file names must be path-safe; no slashes, backslashes, or parent traversal.

## Manifest Shape

```json
{
  "backup_id": "personal_20260625T030000000000",
  "created_at": "2026-06-25T03:00:00",
  "kind": "personal_data",
  "files": [
    {
      "key": "trades",
      "source": "data/trades.json",
      "backup_path": "trades.json",
      "exists": true,
      "size_bytes": 123,
      "sha256": "..."
    }
  ]
}
```

## Testing

Use tmp paths only. Tests should verify:

- backup creates manifest and checksums
- missing optional files are recorded and skipped safely
- preview does not modify current files
- restore requires confirmation
- restore creates a pre-restore backup
- invalid backup ids are rejected

## Completion Definition

R3.0/R3.1 is complete when focused service/API/CLI tests pass, full backend tests pass, docs describe the restore workflow, and `personal_product_readiness_roadmap.md` records R3 first version as complete.
