## TASK H25-00 — Git Baseline

Status: done

Goal:
Ensure the project has a git baseline before functional changes.

Steps:
1. Run `git rev-parse --show-toplevel`.
2. Run `git status --short`.
3. If this is not a git repo:
   * initialize git
   * create a reasonable `.gitignore`
   * create an initial baseline commit

Default tracking policy:
* Track source code, docs, tests, scripts, config, lockfiles, and small required sample files.
* Ignore cache/build/dependency files: `**pycache__/`, `.pytest_cache/`, `.mypy_cache/`, `.ruff_cache/`, `node_modules/`, `frontend/dist/`, `frontend/.vite/`, `.DS_Store`, `.env`, `.env.*`.
* Do not manually delete any file.
* `backend/out/**` is generated output. Ignore it unless an existing doc clearly says a specific file must be versioned.
* `backend/data/**` may contain user data. Track only project-required non-sensitive config/sample files, such as `leaders.json`, `stock_names.json`, or example files.
* Ignore personal trading records, positions, decision journals, market notes, and local fundamentals fill files if present.
* Suggested backend/data ignore examples: `backend/data/trades.json`, `backend/data/positions.json`, `backend/data/decision_journal.json`, `backend/data/market_notes.json`, `backend/data/fundamentals.csv`, `backend/data/fundamentals.json`, `backend/out/`.

Acceptance:
* `git status` works.
* Baseline commit exists, or there is an explicit report explaining why no baseline was created.
* No feature code is modified.
* `.gitignore` includes the chosen policy.
* Any ignored data/output files are listed in the report.

Commit rule:
* H25-00 is the only task in this phase where Claude Code may create a commit automatically.
* The baseline commit message must be: `chore: establish project baseline`
* After H25-00, do not commit unless explicitly requested.

Stop condition:
* Stop only if there is clear risk of committing secrets, credentials, tokens, private account data, or files that appear sensitive and cannot be safely categorized.
