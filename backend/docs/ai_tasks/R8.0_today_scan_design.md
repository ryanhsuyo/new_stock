# R8.0 Today Scan Report Design

Status: implemented in R8.1

## Goal

Make the repeated question "今天掃一下哪些符合規則" reproducible with one backend command.

The report must summarize current generated outputs without recalculating signals or creating a third strategy.

## Inputs

Read only:

- `backend/out/summary.json`
- `backend/out/daily_brief.json`
- `backend/out/universe_report.csv`

Optional later:

- `backend/out/signal_alerts.json`

## Output

New generated report:

- `backend/out/today_scan.json` when CLI is run with `--write-report`

CLI:

- `python3 scripts/today_scan.py`
- `python3 scripts/today_scan.py --json`
- `python3 scripts/today_scan.py --write-report`

## Buckets

The report groups existing rows into:

- `formal_entries`: `internal_signal` is `entry_confirmed` / `ready_to_enter`, or `daily_action` is `enter` / `add`.
- `old_wang_candidates`: `old_wang_flag=true`.
- `steady_momentum_candidates`: `steady_momentum_flag=true`.
- `risk_items`: `internal_signal` is `exit_warning` / `invalidated`, or `daily_action` is `reduce` / `exit`.

## Guardrails

- Do not recompute MA, RSI, market filters, or scores.
- Do not loosen old_wang / steady_momentum conditions.
- Preserve `rules_version` / `rules_metadata`.
- If old_wang market filter is blocked, keep old_wang rows as observation only and add an explicit note.
- Do not edit trades, positions, decision journal, or generated out files except `today_scan.json` through the CLI.

## Acceptance

- Fixed tests prove bucket grouping, sorting, JSON CLI, and write-report behavior.
- Running the CLI on current out files prints the same categories the manual scan produced.
