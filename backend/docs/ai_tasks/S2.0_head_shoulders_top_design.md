# S2.0 Head-and-Shoulders Top Design

Status: implemented

Date: 2026-06-21

## Goal

Detect a conservative head-and-shoulders top and expose it as an explainable
risk signal without letting an unconfirmed pattern force a sell decision.

## Pattern Contract

Add `head_and_shoulders_top` to the existing `PatternResult.pattern_type`
contract. Status values remain unchanged:

* `forming`: right shoulder exists, but close has not broken the neckline.
* `confirmed`: close has reached or broken the neckline within the existing 1%
  confirmation tolerance.
* `failed`: close has exceeded the head by the existing 3% failure tolerance.

The detector returns the existing fields only:

```python
PatternResult(
    pattern_type="head_and_shoulders_top",
    pattern_status="forming",
    neckline=95.0,
    note="頭肩頂形成中：頭部 110.0，頸線 95.0，注意跌破",
)
```

No API or CSV column is added because `pattern_type`, `pattern_status`, and
`neckline` already support generic pattern values.

## Geometry

Use the existing `rows[-120:]` swing-high detection and pairing limits.

For three chronological swing highs:

* `left`: left shoulder.
* `head`: middle peak.
* `right`: right shoulder.

Conditions:

1. Left and right shoulders differ by no more than `_SHOULDER_TOL = 10%` of
   their average.
2. The head is at least `_HEAD_MIN_RISE = 3%` above both shoulders.
3. `left_trough` is the minimum low between left shoulder and head.
4. `right_trough` is the minimum low between head and right shoulder.
5. The conservative horizontal neckline is the lower of the two troughs.
6. The neckline must be at least `_NECKLINE_MIN = 3%` below the lower shoulder
   to reject nearly flat noise.

This mirrors the existing head-and-shoulders bottom implementation while using
the lower trough as the confirmation level. Sloped-neckline regression is out
of scope.

## Status Evaluation

Evaluate after geometry is valid:

1. `failed` when close is greater than `head_high * 1.03`.
2. `confirmed` when close is less than or equal to `neckline * 1.01`.
3. Otherwise `forming`.

Failure is checked first so a decisive breakout above the head cannot be
presented as an active bearish pattern.

## Candidate Priority

Continue selecting the candidate with the newest final anchor date. Preserve
existing tie behavior and insert the new pattern before M top:

1. W bottom
2. Head-and-shoulders bottom
3. Head-and-shoulders top
4. M top

This avoids changing the relative priority of existing patterns. The selected
pattern remains one result per stock.

## Signal Integration

Treat the new pattern exactly like the existing M top risk weighting:

* `forming`: score `-10`; add an explicit forming warning to `risk_note`.
* `confirmed`: score `-20`; add a confirmed neckline-break warning to
  `risk_note`.
* `failed`: no risk penalty; append the detector's failure note to `reasons`.

The total score remains clamped to 0-100 by existing logic. The pattern does
not directly set `SELL`, `exit_warning`, or `invalidated`; the complete trend,
support, holding, and risk logic still determines the final signal.

## Rule Documentation

Before implementation, update `current_rules.md` and `signal_rules.md` to add:

* The new pattern type and geometry.
* Forming is only a warning, not confirmation.
* Confirmation requires a close below the neckline.
* The `-10` / `-20` risk weights and required human-readable explanation.

There is no current conflict: `signal_rules.md` lists minimum required patterns,
not an exclusive allowed set.

## Tests

All tests use fixed synthetic daily bars.

Detector cases:

* Forming head-and-shoulders top.
* Confirmed neckline breakdown.
* Failed pattern after breakout above the head.
* Valid pattern-type set includes `head_and_shoulders_top`.
* No detection when shoulders differ by more than tolerance or the head is not
  sufficiently higher.

Signal cases:

* Forming subtracts 10 from the same baseline score.
* Confirmed subtracts 20 from the same baseline score.
* Forming and confirmed appear in `risk_note`.
* Failed appears in `reasons` and adds no bearish penalty.
* Existing W bottom, M top, and head-and-shoulders bottom tests remain green.

## Scope

In scope:

* Pattern detector and selection priority.
* Pattern model comment/valid-value tests.
* Existing core signal score and explanations.
* Rule, phase, and status documentation.

Out of scope:

* Frontend-specific rendering.
* New API/CSV fields.
* Volume-based pattern confirmation.
* Sloped or regression necklines.
* Automatic trade execution or direct forced sells.
* Changes to trading records, holdings, cash, or generated output files.

## Acceptance Criteria

* Fixed synthetic data produces forming, confirmed, and failed states.
* An unconfirmed pattern cannot be mislabeled confirmed or directly force SELL.
* Score changes always have a matching reason or risk note.
* Existing patterns and API/report schemas remain backward compatible.
* Focused pattern/signal tests and the complete backend suite pass.
