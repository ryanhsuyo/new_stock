> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the product cleanup after consolidating recommendations into two strategies: `old_wang` and `steady_momentum`.

**Architecture:** Keep `core_technical_v2` as the internal signal engine and expose only two recommendation strategies: `old_wang` and `steady_momentum`. Basic fundamentals remain only as a data-quality and basic-risk helper inside `steady_momentum`; `fundamental_*` fields are official helper fields, not an active strategy. Backend remains the source of truth; frontend should display backend-provided fields without recalculating strategy logic.

**Tech Stack:** FastAPI, Pydantic, pytest, CSV/JSON outputs under `backend/out`, React 18 TypeScript frontend only after backend contract is stable.

## Current Baseline

- Backend already writes `strategy_catalog` with only `old_wang_market_chip_rotation` and `steady_momentum_v1`.
- Backend already writes `recommendation_buckets.old_wang` and `recommendation_buckets.steady_momentum`.
- `GET /api/stocks/recommendations` defaults to `steady_momentum`.
- Legacy recommendation query values are currently mapped to `steady_momentum` for compatibility.
- Legacy fundamentals fields still exist in signal rows because they support data completeness, PM workflow, and the 10-point basic-risk helper for `steady_momentum`; they must not be shown or treated as a strategy.
- Frontend strategy selectors expose only `steady_momentum` and `old_wang`; fundamentals wording is scoped to basic-risk / data-completeness support.
