# L3.0 CORS Environment Configuration Design

Status: implemented

Date: 2026-06-21

## Goal

Allow deployments to configure the API's permitted browser origins without
editing source code, while preserving the current local development behavior.

## Problem

`backend/app/main.py` currently hard-codes only
`http://localhost:5173`. A deployment using another hostname must modify code,
and the accepted-origin behavior has no focused tests.

## Selected Interface

Use the optional environment variable `CORS_ALLOWED_ORIGINS`.

```text
CORS_ALLOWED_ORIGINS=https://stock.example.com,http://localhost:5173
```

Rules:

1. Split the value on commas.
2. Trim surrounding whitespace.
3. Remove empty entries.
4. Remove duplicates while preserving the first-seen order.
5. When the variable is missing, blank, or contains only commas/whitespace,
   use `http://localhost:5173`.
6. Reject `*` and fall back to the local default rather than opening this
   trading-data API to every browser origin.

## Architecture

Add `backend/app/config.py` with a small pure function:

```python
def resolve_cors_allowed_origins(env: Mapping[str, str] | None = None) -> list[str]:
    ...
```

`env=None` reads `os.environ`; tests pass an explicit mapping. `main.py` imports
the helper and supplies its result to `CORSMiddleware`.

Configuration parsing stays outside routers and services because it is
application bootstrap logic, not HTTP routing or stock-analysis business logic.

## Runtime Behavior

The app resolves the origins once at process startup. Changing the environment
requires restarting Uvicorn, which matches normal deployment configuration
behavior.

Existing middleware behavior remains unchanged:

* All HTTP methods remain allowed.
* All request headers remain allowed.
* Credential support remains disabled because it is not currently configured.
* The default local frontend origin remains permitted.

## Error Handling

Invalid wildcard configuration logs a warning without exposing other
environment values, then returns the safe localhost default. Missing and blank
configuration are normal and do not log warnings.

No origin URL normalization or DNS validation is added. CORS compares origin
strings, and accepting an administrator-provided explicit origin is sufficient
for this small deployment setting.

## Tests

Create focused tests that do not mutate the process environment globally:

* Missing configuration returns the localhost default.
* Comma-separated origins are trimmed and deduplicated in order.
* Blank configuration returns the localhost default.
* A value containing `*` returns the localhost default and logs a warning.
* A CORS preflight request from a configured origin receives the matching
  `access-control-allow-origin` response header.
* A preflight request from an unconfigured origin does not receive an allow
  origin header.

The preflight tests construct a small FastAPI app with the resolved list; they
do not reload the production module or start a network server.

## Documentation

Update backend operations documentation with:

```bash
export CORS_ALLOWED_ORIGINS="https://stock.example.com,http://localhost:5173"
uvicorn app.main:app --reload --port 9000
```

Mark L3 complete in `status_overview.md` after focused and full backend tests
pass.

## Scope

In scope:

* Environment parsing helper.
* FastAPI CORS middleware wiring.
* Focused configuration and preflight tests.
* Operations and status documentation.

Out of scope:

* Frontend changes.
* Authentication or authorization.
* Reverse proxy configuration.
* Origin regexes or per-route CORS rules.
* Changing methods, headers, or credentials policy.
* Adding dependencies.

## Acceptance Criteria

* Existing local development works without setting an environment variable.
* Multiple explicit deployment origins can be configured without source edits.
* Whitespace, duplicates, blank input, and wildcard input have deterministic
  tested behavior.
* Configured origins pass CORS preflight and unconfigured origins do not.
* Complete backend tests pass without touching real trading data or generated
  outputs.
