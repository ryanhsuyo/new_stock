# R7.0 Rules Version Design

## Goal

Make every generated decision artifact explain which rule version and parameter snapshot produced it.

## Scope

R7 first version adds static rule metadata to outputs. It does not add a settings UI, dynamic parameter editing, or strategy behavior changes.

## Metadata

Expose:

- `rules_version`
- `rules_metadata.version`
- `rules_metadata.strategy_profile`
- `rules_metadata.generated_by`
- `rules_metadata.parameters`
- `rules_metadata.strategies`

The first version uses a stable local version string and a fixed parameter snapshot for the current two-strategy daily system.

## Outputs

The metadata must appear in:

- `summary.json`
- `daily_brief.json`
- `signal_snapshots/signal_snapshot_YYYY-MM-DD.json`
- `signal_snapshot_review.json`
- `signal_alerts.json`

## Boundaries

- Do not change buy/sell rules.
- Do not introduce runtime-editable strategy settings.
- Do not add a database.
- Do not put metadata assembly in routers.
- `rules_version` is audit metadata, not a trading signal.
