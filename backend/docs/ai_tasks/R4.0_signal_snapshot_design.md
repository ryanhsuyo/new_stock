# R4.0 Signal Snapshot And Next-Day Review Design

## Goal

Persist each daily signal plan and compare it with the next available signal run so the system can audit whether yesterday's plan stayed valid, improved, or turned into risk.

## Scope

R4 first version writes generated outputs only:

- `backend/out/signal_snapshots/signal_snapshot_YYYY-MM-DD.json`
- `backend/out/signal_snapshot_review.json`

It does not calculate win rate, portfolio performance, or simulated trades. Those require a longer forward-test design after daily snapshots exist.

## Snapshot

Each snapshot stores `as_of`, `generated_at`, `batch_id`, counts, and one compact item per signal row:

- code, name, close
- internal signal and daily action fields
- key price / invalidation / price plan
- old_wang / steady_momentum strategy flags and scores
- holding shares and position percent

## Review

The review compares the latest previous snapshot before the current `as_of` with the current summary. Outcomes are intentionally conservative:

- `risk_triggered`: previous action was enter / wait / hold, current action is reduce / exit / avoid or signal is exit / invalidated
- `risk_eased`: previous action was reduce / exit, current action is hold / enter / wait
- `action_changed`: daily action changed but not a risk transition
- `unchanged`: same daily action
- `missing_current`: previous code is not in current signals

The review is an audit aid, not a trading signal.

## Integration

`run_daily_signals()` writes the review and snapshot after `summary.json`, `universe_report.csv`, and `daily_brief.json`. The review is computed before writing the current snapshot, so it compares against the last completed prior day.

## Completion Definition

Focused service tests, `run_daily_signals` integration tests, full backend tests, and frontend build pass. Docs list the two new generated outputs.
