# S1.0 Per-Stock Signal Timeout Design

Status: implemented

Date: 2026-06-19

## Goal

Prevent one stock from hanging the full signals batch. A timed-out stock must
produce an explainable unavailable row while later stocks continue normally.

## Scope

In scope:

* Per-stock timeout around `_compute_signal`.
* Explicit timeout fields in `summary.json` and `universe_report.csv`.
* Console/log output containing code, timeout seconds, and step.
* Fixed tests with no real waiting or network access.
* Reconcile stale M3/M4 backlog descriptions before implementation.

Out of scope:

* Parallel signal calculation.
* Timeout protection for backfill or external APIs.
* New notification providers.
* Frontend changes.
* Changes to trading records, holdings, cash, or generated files by hand.

## Selected Architecture

Use a spawn-context `multiprocessing.Pool` with one worker. Submit stocks one at
a time with `apply_async`, then call `get(timeout=...)`.

Why:

* `signal.alarm` is invalid because signals also run in background threads.
* Thread timeouts cannot stop a hung computation.
* A process can be terminated. After timeout, terminate and join the pool,
  create a fresh worker, and continue with the next code.
* One worker preserves current deterministic order and avoids introducing a
  parallel strategy change.

The pool must always be closed/joined on success and terminated/joined on
timeout or unexpected failure. Unexpected worker exceptions still abort the
batch; only the explicit timeout path becomes an unavailable row.

## Configuration

Environment variable:

* `SIGNAL_STOCK_TIMEOUT_SECONDS`
* Default: `20`
* Must parse as a positive float.
* Invalid or non-positive values log a warning and fall back to `20`.

The resolved timeout is recorded in the summary for observability.

## Output Contract

All signal rows add:

* `calculation_status`: `ok` / `data_missing` / `timeout`
* `calculation_error`: empty for normal rows; readable reason otherwise

Timeout rows preserve the stock identity and latest available bar metadata,
but must not contain a buy/sell recommendation:

* `data_ok=false`
* `data_missing=true`
* `signal=DATA_MISSING`
* `internal_signal=DATA_MISSING`
* `score=0`
* `position_size_pct=0`
* `no_buy_reason=訊號計算逾時（超過 N 秒）`
* `risk_note=計算未完成，不可使用此列做交易判斷`
* `reasons` contains the timeout reason

The existing data-missing row builder should be extracted into one helper so
data-missing and timeout rows share a complete, stable field shape. The timeout
path must not call strategy evaluators again while constructing its fallback.

`summary.json` adds:

* `calculation_timeout_seconds`
* `calculation_timeout_count`
* `calculation_timeout_codes`

Existing `data_missing_count` remains backward compatible and includes timeout
rows because both have `data_ok=false`. `no_buy_reason_counts` includes the
timeout reason, so an empty recommendation set stays explainable.

`universe_report.csv` adds:

* `calculation_status`
* `calculation_error`

## Processing Flow

1. Load leaders, OHLCV, positions, and shared context in the parent process.
2. Resolve the timeout configuration once.
3. Create the single-worker spawn pool.
4. Submit one stock and wait for its result.
5. On success, append the row and update reason counts.
6. On timeout, log code/seconds/step, terminate the pool, append a timeout row,
   create a fresh pool, and continue.
7. On any other exception, terminate the pool and re-raise.
8. Close/join the healthy pool before annotations and output writes.
9. Write summary/report files through existing service functions.

## Logging

Timeout output must include:

* stock code
* configured timeout seconds
* step name: `compute_signal`
* statement that processing will continue

Do not print holdings, trades, cash, or private data.

## Testing

Use TDD and a fake pool factory; tests must not sleep or start real workers.

Required tests:

* Default, custom, invalid, and non-positive timeout configuration.
* Normal result receives `calculation_status=ok`.
* Existing short-history result receives `data_missing`.
* Timeout result has the complete unavailable-row contract.
* Timeout terminates/joins the old pool, creates a replacement, and processes
  the next stock.
* Unexpected worker exception terminates the pool and propagates.
* Summary timeout count/codes/seconds are correct.
* CSV contains `calculation_status` and `calculation_error`.
* Full backend suite remains network-independent.

## Documentation Reconciliation

Before production code changes:

* Mark M3 pattern columns complete; implementation and tests already exist.
* Mark M4 macOS/Slack notification support complete; service and tests exist.
* Update `current_rules.md` and `signal_rules.md` with the timeout output
  contract before changing strategy outputs.

## Risks

* Spawn startup adds a fixed cost; one persistent worker limits it to batch
  startup and timeout recovery.
* All worker arguments/results must remain pickle-safe dictionaries/lists.
* A timeout kills the current worker, so no worker may write output files.
  Only the parent process writes summary/report artifacts.
* Formal timing depends on the host; tests verify orchestration with fakes and
  keep one focused smoke check optional rather than relying on wall-clock sleep.
