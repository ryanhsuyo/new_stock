## UX Contract Notes

Status: completed

First-screen sections:

1. Status Strip: data date, latest close price basis, trade output usability, stale / blocked state.
2. Primary Action: one backend-ranked action, one reason sentence, one main action.
3. Today Focus: portfolio risk first, entry candidates second, review / maintenance third.
4. Market Posture: compact risk / trend / sizing tone and note freshness.

Existing reusable fields:

* `pm_worklist.primary_action.title/detail/action_label/action_payload`
* `pm_worklist.today_focus.category/code/name/label/reason/next_action/severity/source/price_basis/as_of`
* `update_service.price_basis_label` and `price_basis_note`
* Universe report price plan fields: entry range, stop / invalidation, target, R/R

Missing or weak display fields:

* `today_focus.short_reason` for compact cards.
* `today_focus.action_label` for button text separate from full `next_action`.
* `today_focus.primary_price` or `primary_metric` for scan-first stock cards.
* Candidate report backend should eventually expose short row text instead of relying on frontend `oneLine` summaries.

Implementation decision:

* Add backend display fields before compacting UI.
* Preserve existing long `reason` and `next_action` fields.
* Frontend may choose layout and truncation, but not derive strategy priority or trading reasons.
