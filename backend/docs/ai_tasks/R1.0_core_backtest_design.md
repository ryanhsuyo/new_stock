# R1.0 Core Backtest Design

Status: implemented

Date: 2026-06-22

## Goal

Build a deterministic single-stock backtester for the existing `core` daily
signal. The first version proves execution timing, trading costs, performance
math, and look-ahead isolation before any portfolio or strategy expansion.

## Scope

In scope:

* One stock code per run.
* Daily OHLCV only.
* Existing `core` internal signal states.
* Historical 0050 market context when available.
* Next-session-open execution with configurable slippage.
* Existing brokerage fee, discount, minimum fee, and sell-tax settings.
* Trades, equity curve, summary metrics, and buy-and-hold comparison.
* Fixed-data service tests and a CLI that writes generated output files.

Out of scope: multi-stock allocation/ranking; Old Wang/current chip or
fundamental-helper data/manual notes; intraday/limit/partial fills; dividends/splits;
shorts/margin/futures/broker integration; API/frontend changes; and edits to
real trades, holdings, cash, or decision journals.

## Architecture

Add `backend/app/services/backtest_service.py` and the thin
`backend/scripts/run_backtest.py` CLI.

`backtest_service.py` owns pure execution, accounting, metrics, validation, and
the core-signal adapter. `run_backtest.py` only parses arguments, loads existing
OHLCV through storage/service helpers, calls the service, writes generated
files, and prints an explainable summary.

Do not add a router. The script writes `backend/out/backtest_summary.json` and
`backend/out/backtest_trades.csv`.

## Configuration

The service accepts a frozen configuration object with these defaults:

| Field | Default | Rule |
|---|---:|---|
| `initial_cash` | 1,000,000 | Must be positive |
| `slippage_bps` | 10 | Non-negative; applied against the trader |
| `lot_size` | 1 | Positive integer; supports odd-lot testing |
| `minimum_history` | 60 | Cannot be below the production signal minimum |
| `force_close` | false | Default preserves an open position at final close |

Trading fee settings come from `load_trading_settings()` unless explicitly
injected in tests. Backtest settings do not modify `backend/data/settings.json`.

## Historical Signal Isolation

For signal date `D`, the adapter receives only rows with `date <= D` for both
the stock and 0050. The engine must never pass the complete future array to the
signal callback.

Backtest mode uses only `data_ok`, `internal_signal`, `data_as_of`, `reasons`,
`risk_note`, and `no_buy_reason` from the `core` result.

Current chip metrics, current fundamentals, sector rotation built from a
present-day universe, positions, and manual market notes are disabled. The
historical market regime/filter is derived only from the truncated 0050 rows.

The adapter must assert `signal.data_as_of == D`. A mismatch stops the run with
an explicit error rather than silently accepting leaked or stale data.

## Event Timing

1. Warm up until at least 60 stock bars exist.
2. Calculate the signal after stock bar `D` closes.
3. Queue at most one action from that signal.
4. Execute the queued action at the next stock bar's open.
5. Mark equity at each bar's close after any opening fill.

Entry states are `entry_confirmed` and `ready_to_enter`. Exit states are
`exit_warning` and `invalidated`.

Other states do not trade. A repeated entry while holding and a repeated exit
while flat are ignored and counted in diagnostics, not recorded as trades.

## Fill And Position Rules

Buy fill:

```text
next_open * (1 + slippage_bps / 10,000)
```

Sell fill:

```text
next_open * (1 - slippage_bps / 10,000)
```

The engine buys the maximum whole `lot_size` quantity affordable after the
brokerage fee. It never uses negative cash or leverage. If cash cannot afford
one lot including fees, the entry is skipped with reason `insufficient_cash`.

Only one long position is allowed. Selling closes the entire position. Fees
and tax use the same rounding rules as `calculate_trade_amounts`; the helper
must accept injected settings so fixed tests do not read user configuration.

## End Of Data

By default an open position remains open. Final equity equals cash plus final
close market value after estimating sell fee and tax. This is not recorded as
a realized trade.

With `force_close=true`, the engine closes at the final close adjusted by sell
slippage, records `forced_close`, and applies sell fee and tax. The summary
states which policy was used.

## Outputs

`backtest_summary.json` contains:

* code, start/end dates, rules version, generated timestamp, and configuration
* initial/final equity, total return, buy-and-hold return, and excess return
* maximum drawdown, closed trade count, win rate, average realized P/L
* total fees, total tax, skipped action counts, and open-position snapshot
* explicit limitations and `lookahead_guard=true`

`backtest_trades.csv` contains one row per fill: signal/fill dates, side,
trigger state/reason, raw/fill prices, shares, gross/fee/tax/net cash flow, and
realized P/L plus holding days on sells.

The service also returns an equity curve for tests. The first CLI does not need
a separate equity-curve file.

## Metrics

* Total return uses final equity versus initial cash.
* Buy-and-hold uses the same first executable open, final close, slippage,
  fees, tax, and lot-size constraints.
* Maximum drawdown uses close-marked equity after costs.
* Win rate and average P/L use closed positions only; no closed trades returns
  `null`, not zero.
* All currency values round to two decimals in outputs; internal calculations
  retain full precision until fee/tax rules require rounding.

No Sharpe ratio or annualization is included in R1.0 because the first target
is correct transaction-level accounting, not an impressive metric count.

## Validation And Errors

Reject with a clear `ValueError` when:

* Rows are empty, unsorted, duplicated by date, or contain invalid OHLCV.
* Configuration is non-positive or nonsensical.
* A signal reports a future/stale `data_as_of`.
* Required output serialization fails.

Insufficient history is a valid completed result with zero trades and a clear
diagnostic. It is not an exception.

## Tests

Fixed network-free tests must cover:

* A close signal fills only at the next open.
* Buy/sell slippage moves prices against the strategy.
* Fee, discount, minimum fee, and sell tax match production rounding.
* Quantity never exceeds cash and respects `lot_size`.
* Repeated states do not duplicate trades.
* Final open-position valuation and optional forced close.
* Total return, drawdown, win rate, and buy-and-hold math.
* The signal callback receives only historical prefixes.
* `data_as_of` mismatch fails loudly.
* Identical inputs produce identical results excluding generated timestamp.
* Insufficient history returns an explainable empty result.
* CLI writes both files under a temporary output directory in tests.

## Acceptance Criteria

* No signal can observe stock or benchmark rows after its signal date.
* Every fill occurs after its triggering signal and includes all configured
  costs.
* Trade cash flows reconcile exactly to final equity.
* Results are deterministic for the same data, rules, and configuration.
* Fixed tests and the complete backend suite pass without real network access.
* No frontend, API schema, real trading data, or formal portfolio record is
  modified.
