## Context

台股快照從 `signals_service` 的每日訊號流程寫出（`write_snapshot_and_review`），美股沒有對應的訊號流程——美股 pipeline 只有回補 OHLCV 加產生報告。但 `build_us_report` 已經呼叫 `_us_watch_rows()` 算出完整分桶，含桶別、動作、觸發價、失效價與目標價。那就是該保存的東西，而且它正是報告當天實際說出口的內容。

美股能產出的最高等級只有「可紙上追蹤」，需要 W 底當日突破且大盤濾網開啟，或趨勢候選在濾網偏多時成立。這種條件不常滿足：2026-07-31 當日是 0 檔。樣本會累積得很慢。

## Goals / Non-Goals

**Goals:**
- 每日保存美股分桶結果，使美股訊號日後可被驗收。
- 前推驗收支援美股，並明確定義只有哪一桶計分。
- 美股證據狀態從「永遠 0 筆」變成「會隨時間累積」。

**Non-Goals:**
- 不改任何美股策略邏輯、參數或分桶規則。
- 不把美股訊號升級為推薦或可下單。
- 不追求短期內產生足夠樣本——條件本來就少見，樣本累積慢是事實不是缺陷。
- 不補建歷史快照。過去的訊號沒有紀錄就是沒有，重算出來的不是當時看到的。

## Decisions

**快照從報告產生器寫出，不另建美股訊號流程。** `_us_watch_rows()` 已經是報告的唯一真相來源；從它寫快照，保證快照與報告內容一致。替代方案是做一個平行的美股 signals 服務，已否決：會出現「報告說 A、快照存 B」的漂移，而這種漂移在事後驗收時無法察覺。

**保存全部桶，只有 ENTER 桶計分。** 觀望與不必看不計入績效，否則就是拿沒發生的進場充樣本。但它們必須保存，因為「當時看到但沒動」是日後最想回答的問題——尤其在濾網關閉的日子。

**出場只用型態低，不用量幅目標。** 紙上追蹤沒有定義停利動作，報告從來沒說「到目標就出場」。用目標價出場等於發明一條當時不存在的規則，而且會系統性美化績效（把贏家封頂、輸家留到停損）。替代方案是同時輸出兩種出場口徑，已否決：兩個數字並列時讀者會挑好看的那個。

**不補建歷史。** 美股 2026-07 以前的訊號沒有紀錄。用今天的資料重算「當時應該看到什麼」會帶進生存者偏差與資料修訂，而這正是 W 底回放 62.4% → 46.1% 那個落差的來源。

**沿用 `generated_at` 進場基準。** 與台股同一套規則，理由相同：訊號在產出之前不存在。

## Risks / Trade-offs

- **樣本累積極慢，證據狀態長期停在「不足」。** → 這是誠實的呈現。報告必須明示樣本數，不得因為數字難看就改口徑或延長窗口。
- **美股報告產生器承擔了寫檔責任，職責變重。** → 快照寫出失敗必須讓該次執行視為失敗，否則會靜默斷掉未來的驗收資料。
- **ENTER 桶條件嚴格，可能長期都是 0 筆而無法區分「策略保守」與「策略無效」。** → 這個限制無法用工程解決；保存其餘桶至少讓日後能做反事實分析。
- **快照格式與台股不同（美股沒有 daily_action / internal_signal）。** → 前推驗收需要市場感知的欄位對應，不要硬套台股欄位名。

## Open Questions

- 美股證據狀態要多少樣本才從「證據不足」轉為呈現統計？台股用的是固定 30 天窗口，美股樣本密度低得多。
- 是否要把美股「觀望但事後突破」的案例做成反事實統計？屬於後續工作，本 change 只保存資料。
