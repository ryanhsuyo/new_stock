## Context

`strategy-portfolio-guardrails` 已完成 17 項任務，護欄邏輯（盤前風險閘門、每日新倉上限、單檔與總曝險上限、停損後再進場間隔）都已實作並在回放中驗證。該 change 當時的決定是不動 production 推薦桶，理由是先確認規則不是只針對單一壓力窗口過擬合。

驗證已完成，現在的問題變成相反方向：production 完全沒有護欄。`generate_strategy_trade_report.py` 的 `_tw_current_rows()` 只用 `daily_action` 與 `internal_signal` 篩選進場候選，`old_wang_market_filter` 僅被讀出來印一行提示文字。`today_scan_service._notes()` 同樣只在 block 時附加說明，不改變清單。

用系統自己的 23 天快照做無前視偏誤前推：54 個 `BUY` 訊號平均 -6.94%、勝率 11.1%、50/54 觸發失效價出場；同期市場中位 -12.09%、0050 -2.42%。護欄回放 2026-07-01→07-29 為 -10.06%、MDD 10.06%，2026-06-01→07-29 為 -20.0%，2026-05-04→07-29 為 +10.0%。護欄不會讓策略轉正，但 7 月窗口確實擋掉 19 筆進場。

現況是：報告每天列出進場候選，使用者無從得知這些候選近期實際為負，而唯一會減少曝險的機制沒有生效。

## Goals / Non-Goals

**Goals:**
- 護欄在 production 進場清單實際生效，被擋候選保持可見。
- 每日報告在結論前呈現當前證據狀態，含同期市場對照。
- 前推驗收可重複執行且無前視偏誤。
- 快照保存風控狀態，使未來驗收不需重算指數。

**Non-Goals:**
- 不調整任何策略參數、閾值或評分。
- 不新增策略，不做多策略拼盤（`CLAUDE.md` §11）。
- 不追求讓回放轉正。本 change 的成功標準是「報告誠實且曝險受控」，不是「績效變好」。
- 不改動賣出、減碼與出場警示路徑。
- 不自動下單，不改 trades/holdings/cash。

## Decisions

**擋單採「移桶」而非「移除」。** 被護欄擋下的候選進入獨立區塊並保留原因，分桶數加總回候選總數。替代方案是直接不列出，已否決：美股報告先前正是因為只渲染部分狀態，導致 AMZN 型態失效後從清單靜默消失，最具決策價值的事件反而看不到。移桶同時滿足既有 spec「被略過的候選 MUST 可稽核，不得無聲消失」。

**護欄邏輯重用回放既有實作，不另建 production 版本。** 盤前風險 helper 與上限計算已存在且有測試。替代方案是為 production 寫一份輕量判斷，已否決：兩份實作會漂移，而漂移的方向必然是 production 比 evaluation 寬鬆。

**前推驗收以 `generated_at` 為可用時點。** 快照的 `as_of` 與 `generated_at` 最多相差 4 天（`as_of=2026-06-26` 對應 `generated_at=2026-06-30`），用 `as_of` 會取得當時尚未存在的訊號。實測兩種基準差異為 -7.17% 對 -6.94%、勝率 5.6% 對 11.1%：結論不變，但偏誤方向是高估，必須修掉。

**證據狀態放在「今日結論」之前。** 替代方案是放報告末尾或附錄，已否決：使用者的閱讀動線是從上往下找今天能買什麼，負面證據放在候選之後等於不存在。

**證據狀態呈現絕對值與市場對照兩行，不做綜合評分。** 替代方案是給一個「策略健康度」分數，已否決：把 -6.94% 與 -12.09% 壓成單一分數會製造精確感，而樣本量根本不支撐。同理不列勝率排名或策略間比較。

**樣本不足時明示而非留白。** 美股沒有快照，樣本數為 0；MUST 印出「尚無可驗收樣本」。留白會被讀成「沒問題」。

**台股輸出三份 per-profile 報告，不做單一合併報告。** 三組 profile 的上限不同，合成一份就必須挑一組當代表，而使用者實際跟哪一套是未知的。替代方案是出一份 combined 報告並附註另兩組差異，已否決：差異出現在「哪幾檔被擋」這種逐列層級，附註表達不了。代價是每日 artifact 從 2 份變 4 份（台股 3 + 美股 1），排程與 Monitor 卡片需相應調整。

**三份報告的曝險上限各自獨立，不跨報告合併。** 每份報告內部的每日新倉與總曝險上限只對該 profile 有效。若同時依三份報告進場，實際曝險最高可達單一 profile 上限的三倍——系統無法阻止這件事，因為它不知道使用者跟了哪幾份。三份報告 MUST 各自印出這個警告。

**`unknown` 盤前風險改為推估等級，但推估只能往保守方向。** 回放的 fail closed 在 production 會造成連續多天空清單。改為由當下可得資料（部分 SPY / QQQ / TSM、或前一交易日殘值）推出等級，輸出 MUST 標示 `degraded` 並列出缺少的輸入。關鍵約束：推估等級 MUST NOT 比可得資料所支持的等級更寬鬆——缺資料不得產生「比較安全」的結論。替代方案是缺資料時預設 normal，已否決：那等於讓資料中斷自動變成放行。

**證據狀態回看窗口固定為近 1 個月。** 以現有快照實測，1 個月窗口有 37 筆訊號、32 筆已出場，勝率 10.8%、平均 -6.35%，與全部 54 筆的 -6.94% 一致，窗口不會落空。替代方案是用全部可用快照，已否決：窗口會隨時間無限拉長，舊訊號的權重與近況混在一起。快照不連續時 MUST 印出實際涵蓋的交易日數而非假設連續。

## Risks / Trade-offs

- **進場候選數量下降，使用者可能認為系統壞了。** → 報告在風控擋下區塊明列每一檔與原因，並在證據狀態說明擋單是預期行為。
- **護欄在多頭段可能擋掉有效訊號。** → 這是已知取捨，回放 2026-05-04 起算窗口為 +10.0% 即包含護欄。本 change 不宣稱護欄提升報酬，只宣稱曝險受控。
- **前推驗收樣本僅 23 天且集中於一段跌勢，結論不可外推。** → 輸出與報告 MUST 標示樣本區間與筆數；不得以此宣稱策略長期無效，也不得以此宣稱有效。
- **既有快照沒有風控欄位，補存只對未來生效。** → 歷史部分維持由指數資料重算，並在輸出標示為重建值而非當時記錄值。
- **三份報告使曝險上限失去意義。** 各 profile 的上限互不知情，同時跟三份等同放大三倍曝險。→ 系統無法在程式層阻止；三份報告 MUST 各自印出警告，說明上限只在單一 profile 內有效。這是本 change 已知且未解決的風險。
- **推估等級會實際決定擋不擋單。** 資料不齊時推出的等級仍會影響真錢決策。→ 推估只能往保守方向，且 MUST 標示 `degraded` 與缺少的輸入，使使用者看得出這天的判斷可信度較低。
- **每日 artifact 從 2 份增為 4 份，排程失敗面變大。** → 任一份失敗不得讓其餘被視為成功；成功標記需 per-artifact。
- **首次出現負面績效陳述，可能促使使用者調參數尋找正報酬。** → 設計上不提供參數面板，證據狀態只讀不寫。

## Migration Plan

1. 先加前推驗收與證據狀態區塊（唯讀，不改任何清單），確認數字與手動驗算一致。
2. 再把護欄接上進場清單，同一份資料日下比對接上前後的候選差異，逐檔確認擋單原因正確。
3. 快照補欄位，只對新產生的快照生效。
4. 回滾方式：護欄接線以單一開關控制，關閉即回到現行行為；證據狀態區塊為純附加，可獨立移除。
